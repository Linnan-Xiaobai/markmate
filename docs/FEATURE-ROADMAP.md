### 2.5 未保存关闭确认

**功能ID**: P0-005  
**优先级**: 🔴 高  
**预计工时**: 6h  
**依赖**: 无

#### 功能描述
关闭窗口、退出程序、或打开新文件时，如果当前文档有未保存的修改，弹出确认对话框提示用户保存。

#### 当前状态
- 点击关闭按钮直接退出，没有未保存提示
- 打开新文件直接替换内容，没有确认

#### 实现方案
**注意**：Electron `window.on('close')` 事件是同步的，但 IPC 是异步的，需要使用以下方案：
1. 主进程在 `close` 事件中调用 `event.preventDefault()` 阻止默认关闭
2. 通过 IPC 询问渲染进程是否可以关闭
3. 渲染进程检查 `isDirty` 状态，决定是否弹出确认框
4. 用户选择后，主进程根据结果决定是否真正退出
- 三个选项：保存、不保存、取消
- 渲染进程内的文件切换（openFile/newFile）直接在前端处理确认，无需主进程介入

#### 文件修改清单
- 修改主进程 [main.ts](file:///d:/Markdown/apps/desktop/electron/main.ts)：添加关闭确认 IPC 流程
- 修改 [use-editor-store.ts](file:///d:/Markdown/apps/desktop/src/store/use-editor-store.ts)：`openFile` 和 `newFile` 前检查脏状态并弹窗确认
- 新增 `confirm-close` IPC 通道

#### 验收标准
- [ ] 点击窗口关闭按钮，有未保存修改时弹出确认
- [ ] 退出程序时有确认提示
- [ ] 打开新文件替换当前内容时有确认
- [ ] "保存"按钮保存后继续关闭
- [ ] "不保存"按钮直接关闭/替换
- [ ] "取消"按钮取消操作，留在当前文件
- [ ] 关闭流程不出现死锁或无法关闭的问题

### 2.6 分屏同步滚动

**功能ID**: P0-006  
**优先级**: 🔴 中  
**预计工时**: 10h  
**依赖**: 无

#### 功能描述
分屏模式下，编辑器滚动时预览区同步滚动到对应位置，反之亦然。

#### 当前状态
- 编辑器和预览区独立滚动，无关联

#### 实现方案
- 基于滚动百分比同步，而非精确行号（更稳定，无需解析内容）
- CodeMirror 滚动监听：通过 `EditorView.scrollDOM` 获取滚动容器，监听 scroll 事件
- 预览区直接监听容器的 scroll 事件
- 使用标志位（isSyncing）防止循环触发，而非防抖（保证响应速度）
- 只在 split 模式下启用同步
- 可选：后续可优化为基于标题的精确同步（需解析文档结构）

#### 文件修改清单
- 修改 [Editor.tsx](file:///d:/Markdown/apps/desktop/src/components/Editor.tsx)：暴露滚动容器引用和滚动方法
- 修改 [Preview.tsx](file:///d:/Markdown/apps/desktop/src/components/Preview.tsx)：暴露滚动容器引用
- 修改 [App.tsx](file:///d:/Markdown/apps/desktop/src/App.tsx)：添加滚动同步协调逻辑

#### 验收标准
- [ ] 分屏模式下编辑器滚动，预览区同步滚动
- [ ] 预览区滚动，编辑器也同步滚动
- [ ] 编辑/预览单独模式下不同步
- [ ] 滚动同步流畅，无明显抖动
- [ ] 不会因为同步导致循环触发或死循环
- [ ] 大文件下同步依然流畅

## 8. 风险分析与应对措施

### 8.1 打包体积风险

| 库 | 预估体积 | 风险等级 | 应对措施 |
|----|----------|----------|----------|
| highlight.js | ~200-500KB（全语言） | 🟡 中 | 按需导入常见语言（js/ts/py/go/rust/cpp/java/md等），预计 ~100KB |
| katex | ~300KB JS + ~200KB CSS | 🟡 中 | 可接受，数学公式是核心需求；CSS必须包含 |
| mermaid | ~1-1.5MB | 🔴 高 | 强制懒加载（动态 import），不打开含图表的文档不加载 |
| FlexSearch（全局搜索）| ~100KB | 🟢 低 | 可接受，搜索功能是常用功能 |

**总体积控制目标**：新增依赖不超过 1MB（gzip 后），mermaid 懒加载不计入初始加载体积。

### 8.2 性能风险

| 功能 | 风险点 | 应对措施 |
|------|--------|----------|
| 多标签页 | 多个编辑器实例内存占用高 | 非活动标签只保存内容，不保留编辑器实例；切换时重建；限制最大标签数（如 15个） |
| 同步滚动 | 大文档下滚动事件触发频繁 | 使用 requestAnimationFrame 节流；标志位防止循环；大文件下可考虑降级或关闭 |
| 文件树 | 目录文件过多渲染卡顿 | 当前已有 MAX_DIRECTORY_ITEMS=2000 限制；后续可实现虚拟滚动 |
| Mermaid 渲染 | 大文档多个图表渲染阻塞 | 图表懒渲染（滚动到视口才渲染）；渲染在空闲时间进行 |
| 全局搜索 | 大文件夹搜索阻塞UI | 必须使用 Web Worker；分批返回结果，不一次性返回全部 |

### 8.3 安全风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| DOMPurify 为支持 Mermaid SVG 放宽规则 | XSS 攻击 | 不要全局放宽 DOMPurify；Mermaid 处理放在 sanitize 之后，mermaid 库自身会处理安全；对 mermaid 生成的 SVG 再次做安全检查 |
| 配置文件被篡改注入恶意值 | 应用异常/崩溃 | 配置读取有 Schema 校验；非法值回退到默认；配置文件损坏时自动重置 |
| 文件路径遍历 | 读取任意文件 | 主进程文件操作已有基本路径校验；打开文件夹时限制在所选目录内 |
| 外链安全 | 钓鱼/恶意网站 | 当前已有 `rel="noopener noreferrer"` 处理外部链接，保持现状 |

### 8.4 技术债务与回归风险

| 风险点 | 影响 | 应对措施 |
|--------|------|----------|
| 多标签页重构 store | 现有功能回归 | 充分测试；先在独立分支开发；小步提交 |
| 主题切换改造所有组件颜色 | 样式遗漏/显示异常 | 逐一组件检查；使用 CSS 变量后容易全局替换；保留深色主题为默认 |
| 新增 IPC 接口 | 主进程/渲染进程不同步 | TypeScript 类型共享；preload 有完整类型定义 |

### 8.5 功能复杂度分级

| 功能 | 复杂度 | 建议 |
|------|--------|------|
| 侧边栏拖拽、未保存确认、同步滚动 | 低 | 最先实现，快速建立信心 |
| 设置面板、文件树递归、代码高亮、自动保存、搜索替换、大纲导航 | 中 | 按排期实现 |
| 亮色主题、数学公式、图片粘贴、打印、最近文件 | 中高 | 注意样式适配和边界情况 |
| 多标签页、Mermaid、HTML/PDF导出、全局搜索 | 高 | 需要详细设计和充分测试 |
| WYSIWYG编辑、插件系统 | 极高 | v1.0后再考虑，提前做架构预留 |
